# MIUNLOCK

Android-приложение (Java + C++/JNI) для автоматической подачи заявки на разблокировку загрузчика Xiaomi
через Mi Community API, с привязкой момента отправки к сбросу суточной квоты по NTP-времени.

Приложение общается ровно с двумя группами хостов: NTP-серверы (UDP/123) и хосты Xiaomi
(`account.xiaomi.com`, `sgp-api.buy.mi.com`, `c.mi.com`). Телеметрии нет, сторонних SDK нет.

**Честно о результате.** Квота на подачу заявок живёт на сервере Xiaomi: в сутки проходит ограниченное
число запросов, и они разбираются за миллисекунды. Это приложение не «обходит» квоту — оно лишь даёт
вашей единственной попытке уйти максимально точно в момент сброса и успеть на порядок раньше ручного
ввода. Гарантии слота не существует ни у одного подобного инструмента.

## 3. Как устроен тайминг

1. **NTP.** `ntp_query()` шлёт 48-байтовый клиентский пакет на `time.google.com`, `pool.ntp.org`,
   `time.cloudflare.com`, `ntp.aliyun.com` (список настраивается). Проверяются mode, stratum,
   leap-индикатор, а также совпадение поля originate с нашим transmit — это отсекает подсунутые ответы.
   Смещение считается по стандартной формуле `((t2-t1)+(t3-t4))/2`, задержка `(t4-t1)-(t3-t2)`.
2. **Отбор выборки.** Из нескольких ответов берётся образец с минимальным RTT, к нему присоединяются
   только те, чей интервал достоверности пересекается с ним. Итоговое смещение — средневзвешенное по
   `1/rtt`, погрешность — максимум отклонения плюс корневая дисперсия сервера. В типичной сети это
   единицы миллисекунд.
3. **Доверенное время.** `trusted_now_ms = CLOCK_REALTIME + смещение + ручная поправка`. UI рисует
   именно его, а не часы телефона.
4. **Цель.** `Schedule.resolve()` считает ближайшие 00:00 Asia/Shanghai (UTC+8) — это и есть момент сброса
   квоты. Прежние 19:00 МСК и 17:00 МСК оставлены пресетами. Отдельно: **00:00 Пекин = 19:00 МСК**,
   17:00 МСК — это другое время (22:00 Пекин), пресет существует лишь потому, что он был в задании.
5. **Будильник.** `setExactAndAllowWhileIdle(RTC_WAKEUP)` работает по системным часам, поэтому целевое
   доверенное время переводится в системную шкалу: `wall = target - (trustedNow - systemNow)`.
   Будильник ставится на `target - prepareLead` (по умолчанию за 60 с).
6. **Прогон.** По будильнику поднимается foreground service, берётся `PARTIAL_WAKE_LOCK`, при
   необходимости делается свежий NTP-синк, и вызывается нативное ядро. Ядро живёт в шкале
   `CLOCK_BOOTTIME` (она, в отличие от `CLOCK_MONOTONIC`, не останавливается при уходе устройства в
   сон): `deadline = boottime_now + (target - trusted_now)`.
7. **Выстрел.** Спим до `deadline - preconnectLead` (ровно 500 мс), в этот момент Java прогревает DNS,
   TCP, TLS и кладёт соединение в пул OkHttp. Затем спим до `deadline - spinThreshold` и последние
   ~6 мс крутимся в горячем цикле без сна. Первая попытка уходит на `deadline - earlyOffset - jitter`
   (по умолчанию 120 мс раньше + случайные 1–50 мс), потому что запрос должен прийти на сервер к
   моменту сброса с учётом сети, а не после. Далее — повторы в течение окна (по умолчанию 2.5 с,
   интервал ~220 мс + джиттер), пока ответ не станет окончательным.
8. **Ответы.** Повтор выполняется только на сетевых ошибках и неизвестных кодах. «Слоты кончились»,
   блокировка, истёкший токен и «заявка принята» завершают прогон немедленно — долбить сервер
   бессмысленно и заметно.

## 4. Что уходит в сеть

Приложение не изобретает заголовков: лишний нестандартный заголовок — сам по себе признак бота.

* Вход: `GET https://account.xiaomi.com/pass/serviceLogin?sid=mi_community&_json=true`,
  затем `POST /pass/serviceLoginAuth2` с полями `sid`, `hash` (MD5 пароля в верхнем регистре),
  `user`, `callback`, `qs`, `_sign`, `_json`; затем переход по `location` (SSO) и сбор `Set-Cookie`.
  Пароль уходит только на `account.xiaomi.com` и нигде на устройстве не сохраняется.
* Apply: `POST https://sgp-api.buy.mi.com/bbs/api/global/apply/bl-auth`, тело `{"is_retry":true}`.
* Статус: `GET https://sgp-api.buy.mi.com/bbs/api/global/user/bl-switch/state`.
* Выход: `GET https://sgp-api.buy.mi.com/bbs/api/global/user/login-out`.
* Cookie: `new_bbs_serviceToken=<токен>;versionCode=500411;versionName=5.4.11;deviceId=<id>;`
* Заголовки: `Cookie`, `User-Agent: okhttp/4.12.0` (как у официального клиента), `Content-Type` для POST.
  `Accept-Encoding` намеренно не задаётся вручную — иначе OkHttp перестал бы прозрачно распаковывать
  ответ, а подмена значения ничего не даёт.

## 5. Антидетект: что делается и что нет

Делается:

* стабильный `deviceId` (40 hex, генерируется один раз, SHA-1 от случайных данных и времени, лежит в
  шифрованном хранилище) — смена идентификатора на каждой попытке как раз и выглядит подозрительно;
* User-Agent официального клиента и никаких выдуманных заголовков;
* случайный разброс 1–50 мс на каждую попытку и случайные интервалы повторов — машина, стреляющая в
  одну и ту же миллисекунду, видна сразу;
* ограниченный бюджет повторов (окно + максимум попыток), а не бесконечный цикл;
* метка попытки (`SHA-1(deviceId|номер|время|нонс)`) пишется только в журнал и **не** отправляется на
  сервер. Рисовать подписи к запросам мы не стали: неверная подпись — гарантированный отказ, а верную
  без закрытого протокола не воспроизвести.

Не делается (и не может быть сделано честно): подмена подписи запроса, обход серверной квоты,
эмуляция «живого» поведения пользователя в приложении сообщества.

## 6. Сборка

Требуется Android Studio (Ladybug или новее) либо Gradle 8.7 + JDK 17 + Android SDK 34 + NDK 26.1.10909125
(CMake 3.22.1 ставится из SDK Manager).

```bash
# Вариант 1: Android Studio
#   Open -> каталог проекта; stub wrapper подхватится и докачает Gradle сам.

# Вариант 2: из консоли
gradle wrapper --gradle-version 8.7     # один раз, создаёт gradle/wrapper/gradle-wrapper.jar
./gradlew assembleDebug
apk: app/build/outputs/apk/debug/app-debug.apk
```

`gradle/wrapper/gradle-wrapper.jar` — единственный бинарный файл, которого нет в репозитории
(он не скачивается в офлайн-сборке и его легко восстановить командой выше). `gradle-wrapper.properties`
на месте, версии зафиксированы: AGP 8.5.2, Gradle 8.7, `minSdk 24`, `targetSdk 34`.

После установки: выдать разрешения «Уведомления» и «Точные будильники» (Android 12+ сам откроет
соответствующий экран по нажатию ARM), отключить для приложения оптимизацию батареи в прошивках
с агрессивным энергосбережением (MIUI/HyperOS, EMUI, ColorOS) — иначе будильник может не разбудить
устройство.

## 7. Тесты

Нативное ядро собирается и проверяется без Android SDK:

```bash
./tools/run_native_tests.sh
```

Покрыто: векторы SHA-1, формат device-id и cookie, конвертация NTP-таймстампов (секунды и дробная
часть), ISO-8601, а также поведение снайпера на виртуальных часах — первая попытка уходит на
121–170 мс раньше цели, прогрев ровно за 500 мс, повторы с интервалом 200–251 мс, ограничение окном,
остановка по одной команде, корректный JSON-отчёт и ручная поправка времени в `TimeStore`.

Java-слой и ресурсы в этом окружении скомпилировать нельзя (нет Android SDK/JDK), поэтому UI
проверялся статически: соответствие `binding.*` идентификаторам разметки, наличие каждого `native`
метода в JNI-мосте и обратно, ссылки на члены классов. Первую сборку всё равно нужно сделать у себя
и посмотреть на результат глазами.

## 8. Что осталось проверить на живом устройстве

* **Шаг SSO при входе.** `serviceLoginAuth2` отдаёт `serviceToken`, но `new_bbs_serviceToken` —
  cookie домена сообщества, и на неподтверждённых аккаунтах Xiaomi может потребовать капчу или 2FA.
  Код прохода по `location` и `c.mi.com/global/` написан, ошибки не глотаются, но на реальном аккаунте
  не проверялся. Если токена нет — в `LoginActivity` есть поле ручной вставки: значение
  `new_bbs_serviceToken` из cookie браузера на `c.mi.com` (так делают все публичные реализации,
  включая `offici5l/MiCommunityTool` и `matedon/xiaomi_bypass_bootloader_unlock_quota`).
* **Коды ответов.** `code 0 + apply_result 1/3/4`, `100001`, `100003`, `100004` и `button_state 1/2/3`
  разобраны по публичным реализациям; Xiaomi меняет их без предупреждения, поэтому незнакомый код
  логируется целиком, а не молча проглатывается.
* **Реальная точность.** В песочнице UDP/123 закрыт, поэтому NTP-обмен проверен только по коду и
  математике, а не «в бою». На телефоне смотрите на строку статуса: смещение, ±погрешность, RTT.
  Погрешность больше 30 мс — повторите синк или смените сервер.

## 9. Приватность

Никакой аналитики, crash-репортеров и сторонних серверов. Пароль не сохраняется. Токен сессии и
device-id лежат в AES-256-GCM с ключом в AndroidKeyStore; настройки — в обычных SharedPreferences.
Логи существуют только в памяти процесса и logcat, на диск не пишутся. Бэкапы приложения отключены
(`allowBackup=false`). Разрешений, кроме сети, будильников, wakelock и уведомлений, не запрашивается.

## 10. Юридическая заметка

Автоматизация действий в аккаунте может нарушать пользовательское соглашение Xiaomi; инструмент
работает только с вашим аккаунтом и не обходит аутентификацию. Разблокировка загрузчика снимает
гарантию и стирает данные. Ответственность за использование — на вас.
